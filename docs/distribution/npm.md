# npm distribution

The package and executable are both named `portloom`. The repository's root package is private to prevent accidental publication. Only the archive generated by `scripts/release/pack.mjs` is intended for the registry.

## Build and validate

```sh
npm run verify
npm run build
python3 scripts/dev/terminal_smoke.py
python3 scripts/dev/language_smoke.py
npm run pack
node scripts/release/smoke.mjs
npm publish ./dist/npm/portloom-1.1.0.tgz --dry-run --access public
```

The packer reads the shared Cargo version and `distribution/npm/metadata.json`. It verifies each binary's version and SHA-256, dependency notices and advertised platforms, then generates the manifest from an allowlist of fields and files. The English package README lists only included platforms and links to French documentation.

The archive contains a POSIX `exec` launcher, binaries, dependency notices, Rust sources and tests, license, README and checksums. It has no npm dependencies or installation hooks. Language selection belongs to the first interactive application launch; installation never prompts. The smoke test installs into a temporary prefix and verifies metadata, native execution, JSON, both help languages and a simulated HTTP probe.

## Platforms

| Native package | Rust target |
| --- | --- |
| darwin-arm64 | aarch64-apple-darwin |
| darwin-x64 | x86_64-apple-darwin |
| linux-arm64 | aarch64-unknown-linux-gnu |
| linux-x64 | x86_64-unknown-linux-gnu |

The GitHub workflow builds and tests each target natively, then combines all four into `portloom-npm`. It never publishes to npm. Linux builds use Ubuntu 22.04 and glibc; Windows and musl are unsupported. A local build only establishes support for its own platform.

## Maintainer publication

Verify the source commit, successful CI and final archive checksum before publishing. Never rebuild different sources under an existing release tag.

```sh
npm publish ./dist/npm/portloom-1.1.0.tgz --access public
npm run release:status
```

Actual publication is an explicit maintainer action. `release:status` only reads the registry and fails if the expected version is unavailable. An accepted publish request does not prove that the version is publicly distributed.

If npm displays `0.0.0-stage` / “Temporary Holding Version”, inspect the public version with `npm view portloom`. `npm stage list portloom` lists staged publications accessible to the account. An empty list alone does not establish whether manual approval is needed; also inspect the publish result and registry status.

References: [npm manifest](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/), [staged publishing](https://docs.npmjs.com/staged-publishing/), [npm stage](https://docs.npmjs.com/cli/v11/commands/npm-stage/).
